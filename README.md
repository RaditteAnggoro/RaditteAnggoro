I build developer tools and business workflow systems that stay understandable when
the project becomes complicated. My current work covers visual React development,
local device diagnostics, reusable coding-agent workflows, and multi-tenant messaging.

I care about clear source code, honest limitations, local-first workflows, useful
documentation, and tests that support the claims made in a README.

## Featured work

### [React UI/UX Tool](https://github.com/RaditteAnggoro/react-uiux-tool)

A local-first visual editor for real React projects. It inspects JSX/TSX, previews
supported applications, and writes validated drag-and-drop changes back to normal
source files for Git review.

`TypeScript` · `React` · `Vite` · `Playwright` · `visual editor`

### [One UMS Portal](https://github.com/RaditteAnggoro/one-ums-portal)

A portfolio-grade unified messaging platform with multi-stage approvals, campaign
queues, tenant governance, audit evidence, and exact budget reservations. Delivery
is simulated by default, so the repository can demonstrate the complete workflow
without pretending that live providers are connected.

`TypeScript` · `Next.js` · `NestJS` · `PostgreSQL` · `Redis` · `BullMQ`

### [Agent Doctor For Your Devices](https://github.com/RaditteAnggoro/agent-doctor-for-your-devices)

A local Go CLI and agent skill for explainable device maintenance. It reviews junk
candidates, duplicates, applications, and performance evidence before the user
decides whether anything should be moved to Trash.

`Go` · `CLI` · `local-first` · `privacy` · `device maintenance`

### [Skills for Lazy Developer](https://github.com/RaditteAnggoro/skill-for-lazy-developer)

Eight focused Codex engineering workflows for debugging, implementation,
architecture, browser diagnostics, planning, release review, and evidence-backed
verification.

`Codex` · `agent skills` · `Python` · `software engineering` · `verification`

## How I approach projects

- Explain what works today and keep known limitations visible.
- Prefer normal source files and established project tools over hidden formats.
- Keep local workflows private by default and avoid unnecessary telemetry.
- Record licenses, third-party notices, credits, and sources of inspiration.
- Make examples safe to run with synthetic data and simulated external effects.
